# Post-Mortem Reports

This directory documents significant development efforts, their rationale, methodology, and lessons learned. A report should be placed here before or immediately after merging a substantial branch.

## Purpose

A post-mortem report should cover:
- **What was done**: Tasks completed and features implemented
- **Why it was done**: Problem addressed, goals, intended impact
- **How it was done**: Technical approach, key decisions
- **What was learned**: Insights, unexpected challenges, successful strategies
- **Impact Assessment**: Performance, stability, adherence to design goals

## Naming Convention

`YYYY-MM-DD_snake_case_description.md`
